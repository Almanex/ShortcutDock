# AI_CONTEXT.md — Архитектурный контекст ShortcutDock

Настоящий документ является полным техническим описанием архитектуры, технологического стека, ключевых паттернов и инженерных решений проекта **ShortcutDock**. Документ предназначен для передачи контекста разработчикам и искусственному интеллекту для безопасной поддержки и развития кодовой базы.

---

## 1. Суть проекта и Стек

**ShortcutDock** — легковесная нативная док-панель для операционной системы Windows 11, обеспечивающая быстрый запуск программ, файлов и управление активными окнами.

### Технологический стек
* **Язык программирования:** C# 12
* **Платформа:** .NET 10.0 (Windows Desktop)
* **GUI-Фреймворк:** WPF (Windows Presentation Foundation)
* **Основные библиотеки (версии из `ShortcutDock.csproj`):**
  * `WPF-UI` (v4.3.0) — современные элементы управления в стиле Fluent Design, системный трей, синхронизация с темами Windows.
  * `CommunityToolkit.Mvvm` (v8.4.2) — архитектура MVVM, генерация шаблонного кода свойств и команд.
  * `System.Drawing.Common` (v10.0.9) — работа с системной графикой и извлечение иконок.
* **Низкоуровневое взаимодействие:** Native Win32 API (`user32.dll`, `shell32.dll`, `dwmapi.dll`) через P/Invoke.

## 2. Архитектура и Паттерны

Проект строго следует шаблону проектирования **MVVM (Model-View-ViewModel)** и разделен на несколько логических слоев:

```
src/ShortcutDock/
├── Models/         # Модели данных (Сериализация настроек)
├── ViewModels/     # Бизнес-логика, управление состоянием
├── Services/       # Системные службы (AppBar, логирование, запуск)
├── Native/         # Описание Win32 структур и P/Invoke импортов
└── Views (Root)    # Файлы разметки XAML и их code-behind
```

### Разделение ответственности и паттерны
* **Управление состоянием (MVVM):** Вся бизнес-логика панелей находится в `MainViewModel`, а логика конкретного ярлыка — в `ShortcutViewModel`. Команды привязаны через RelayCommand генераторы.
* **Слой хранения (Services):** `SettingsService` осуществляет сериализацию и чтение конфигурационного файла `settings.json` в формате UTF-8 с поддержкой раскрытия переменных окружения (например, `%AppData%`).
* **Разрешение путей (COM):** `ShortcutResolver` использует COM-интерфейсы `IShellLinkW` и `IPersistFile` для низкоуровневого парсинга ярлыков `.lnk` без вызова громоздкого Windows Script Host.
* **Интерфейс (Views):** Разметка окон полностью отделена от логики. Однако интерактивные ресурсоемкие эффекты (волновое увеличение и автоскрытие) вынесены в `code-behind` (`MainWindow.xaml.cs`) для быстрого прямого обращения к визуальному дереву без промежуточного биндинга.

## 3. Реализованная логика (Current State)

В проекте реализованы и стабильно функционируют следующие модули:

* **Интеграция с рабочим столом (AppBar):** Окно регистрируется в системе как панель приложений (`SHAppBarMessage` с флагом `ABM_NEW`). Это резервирует физическое пространство на экране, заставляя другие развернутые приложения подстраиваться под границы дока.
* **Динамическое автоскрытие (Auto-Hide):** При потере фокуса панель плавно уезжает за пределы монитора. На границе экрана остается 2-пиксельный триггер для вызова панели. В скрытом состоянии резервирование экрана отключается, возвращая окнам 100% пространства.
* **Индикаторы процессов:** Раз в 1.5 секунды фоновый таймер сканирует запущенные процессы и подсвечивает активные программы точкой.
* **Фокусировка окон вместо запуска:** Клик по запущенному приложению перехватывает запуск и восстанавливает существующее окно (`SetForegroundWindow`), предотвращая запуск дубликатов.
* **Интерактивная волна (Hover Zoom):** Плавное масштабирование значков при наведении курсора мыши по формуле Гаусса.
* **Синхронизация тем оформления:** Автоматическое отслеживание изменений темы Windows (светлая/темная) с перерисовкой Mica/Acrylic размытия в реальном времени.

## 4. Ключевые решения и Костыли (Context & Workarounds)

> [!WARNING]
> Ниже перечислены критически важные инженерные решения и обходы багов. **Не пытайтесь оптимизировать этот код стандартными методами**, так как это гарантированно приведет к регрессии.

### 1. Предотвращение бесконечного цикла рекурсии AppBar
* **Файл:** [AppBarService.cs](file:///d:/Develop/tsreen/src/ShortcutDock/Services/AppBarService.cs#L343-L352)
* **Проблема:** Windows рассылает системное сообщение `WM_SETTINGCHANGE` при каждом изменении рабочей области. Метод `UpdatePosition()`, вызывающий Win32 API `SHAppBarMessage(ABM_SETPOS)`, сам провоцирует рассылку этого сообщения. Без предохранителя `WndProc` уходил в бесконечную рекурсию, зависая и сбрасывая регистрацию панели.
* **Решение:** Внедрен флаг-предохранитель `_isUpdating`. Входящие сообщения `WM_SETTINGCHANGE` игнорируются, если в этот момент выполняется внутренний расчет позиционирования:
```csharp
if (!_isUpdating)
{
    UpdatePosition();
}
```

### 2. Выравнивание структуры SHQUERYRBINFO для x64
* **Файл:** [RecycleBinService.cs](file:///d:/Develop/tsreen/src/ShortcutDock/Services/RecycleBinService.cs)
* **Проблема:** Структура `SHQUERYRBINFO` имела разметку `Pack = 4`. На 64-битных системах Windows ожидает выравнивание по умолчанию (размер структуры 24 байта вместо 20). Из-за этого вызов `SHQueryRecycleBin` падал с ошибкой `E_INVALIDARG` (0x80070057), а статус Корзины всегда определялся как пустой.
* **Решение:** Удален атрибут `Pack = 4`. Система теперь использует нативный размер структуры в зависимости от разрядности ОС.

### 3. Исключение дрожания панели при анимации отскока (Bounce)
* **Файл:** [MainWindow.xaml](file:///d:/Develop/tsreen/src/ShortcutDock/MainWindow.xaml) / [MainWindow.xaml.cs](file:///d:/Develop/tsreen/src/ShortcutDock/MainWindow.xaml.cs#L352-L362)
* **Проблема:** Когда анимация отскока применялась к `IconContainer`, элемент смещался по координате Y. Из-за этого курсор мыши выходил за пределы контейнера, что генерировало ложное событие `MouseLeave`. Масштаб сбрасывался, курсор снова оказывался над иконкой, вызывая `MouseEnter`. Это вызывало хаотичное дрожание всей панели.
* **Решение:** Анимация прыжка перенесена на дочерний элемент **`Image`** (`IconImage`), а сам родительский контейнер с мышью остается статичным на своем месте.

### 4. Конфликт WPF-анимаций и ручного масштабирования Hover Zoom
* **Файл:** [MainWindow.xaml.cs](file:///d:/Develop/tsreen/src/ShortcutDock/MainWindow.xaml.cs#L581-L584)
* **Проблема:** В WPF запуск анимации на свойстве блокирует его для прямой ручной перезаписи. При возврате иконок в исходный размер с помощью `DoubleAnimation` свойство `ScaleX` блокировалось, и последующие перемещения мыши не давали эффекта масштабирования.
* **Решение:** Перед ручным расчетом масштаба в `Window_PreviewMouseMove` анимация принудительно сбрасывается передачей `null`:
```csharp
scaleTransform.BeginAnimation(ScaleTransform.ScaleXProperty, null);
scaleTransform.BeginAnimation(ScaleTransform.ScaleYProperty, null);
```

### 5. Обход валидации путей для виртуальных директорий
* **Файл:** [ProcessLauncher.cs](file:///d:/Develop/tsreen/src/ShortcutDock/Services/ProcessLauncher.cs)
* **Проблема:** Запуск Корзины происходит по GUID пути `shell:::{645FF040-5081-101B-9F08-00AA002F954E}`. Метод проверки существования файлов `File.Exists` возвращал `false`, прерывая запуск.
* **Решение:** Проверки существования файлов отключаются, если путь начинается с `shell:`, `http:`, `https:` или содержит GUID-конструкции `:::{`.

## 5. Требования к окружению (Environment)

Приложение является нативным десктопным клиентом и не требует внешних баз данных, файлов `.env` или контейнеризации.

### Требования
* **ОС:** Windows 10/11 (x64)
* **SDK:** .NET 10.0 SDK или выше

### Команды сборки и запуска
* **Локальный запуск в режиме отладки:**
  ```powershell
  dotnet run --project src/ShortcutDock/ShortcutDock.csproj
  ```
* **Очистка и компиляция решения:**
  ```powershell
  dotnet clean ; dotnet build
  ```
* **Публикация единого независимого исполняемого файла (Production Build):**
  ```powershell
  dotnet publish src/ShortcutDock/ShortcutDock.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
  ```
  Исполняемый файл будет скомпилирован по пути: `src/ShortcutDock/bin/Release/net10.0-windows/win-x64/publish/ShortcutDock.exe`

## 6. Технический долг и Известные проблемы

* **Отслеживание UWP/Store приложений:** Текущий трекер процессов работает по путям исполняемых файлов. UWP-приложения запускаются внутри контейнера `ApplicationFrameHost.exe`, поэтому трекер не может сопоставить их оригинальный путь и не отображает под ними точку активности.
* **Периодический опрос процессов:** Вызов `Process.GetProcesses()` раз в 1.5 секунды создает незначительную, но регулярную нагрузку на систему. В перспективе опрос следует заменить на прослушивание системных WMI-событий создания/уничтожения процессов.
* **Многомониторные конфигурации:** AppBar привязывается к тому монитору, на котором инициализировано окно, но в интерфейсе настроек отсутствует ручной выбор конкретного дисплея для размещения панели.
